# pairwise-gbuffer-compression

4K 分辨率下 G-Buffer 带宽直接吃满，法线用三通道 8bit 存，解码后单位向量长度不为 1，光照出现方向偏差；粗糙度与金属度打包进同一张图，采样时通道顺序在不同 pass 里写反；模板位被描边和透明裁剪共用，后处理读到的材质 id 被覆盖；MSAA 下 G-Buffer 按像素而非样本存储，边缘几何的法线被平均成斜面；速度缓冲只写动态物体，相机移动时静态场景的时域效果全部错位；深度精度按近远平面线性分布，远处 z-fighting 让贴花闪烁；清屏只清了颜色没清法线，未绘制区域残留上一帧的方向；贴花 pass 写入 G-Buffer 时没做材质混合，金属度被贴花直接覆盖成零；压缩格式在有符号法线的高亮区出现块状色阶；延迟光照 pass 与前向透明 pass 共用同一套 G-Buffer 布局，通道解释不一致。render/gbuffer_compression.py 是核心，tests/test_gbuffer_compression.py 15个红。要修的是：法线用八面体编码；通道打包顺序统一；模板位分区；MSAA 按样本存储；速度缓冲覆盖全屏；深度改反向 Z；清屏补齐所有附件；贴花按材质混合；编码加误差补偿；前向与延迟布局分表。

## 运行

```bash
python -m pytest tests -q
```

初始状态：15 个用例失败。修复实现使全部用例通过，不要修改 `tests/` 下的测试。
